# 04. EDITORIAL PRINCIPLE & TONE

---

## 1. 最重要原則 [VALIDATED]

> **事実を増やさない。事実は面白く料理していい。**

### 例

Source Fact:

```
9:00–12:00
草刈り
初心者可
```

**OK**（事実の料理）:

> 「土曜の朝から3時間、草を刈る。予定が『草刈り』になる週末、なかなかない。」

**NG**（事実の追加）:

> 「自然の中でストレス解消」

### Fact として追加してはいけないもの

Source に書かれていない、

- 健康効果
- ストレス解消
- 達成感
- 人との交流
- 景色
- 難易度
- 感想

一人称体験を捏造しない。

### 実装上の強制

- `listings` の fact カラム（`title` / `description` / `work_type` / `pay_*` / `location_*` /
  `qualification_*` / dates）は Source 由来の値のみ。
- 編集コピーは `listings.editorial_note`（肉体副業メモ）にのみ書く。人間記入・任意。
  存在する場合のみ詳細ページに表示し、「肉体副業メモ」というラベルを付けて Fact と視覚的に分離する。
- 個別案件について、Source Fact にない身体的影響等を断定しない。

## 2. TONE [VALIDATED]

30代の友人同士くらい。少し雑。少し自虐。具体的。説教しない。
wellness / self-help 調にしない。

### 避ける表現

- いかがでしたでしょうか
- 〜ではないでしょうか
- 「おすすめです」の連発
- 魅力の一つです
- 近年注目されています
- 現代社会において
- 忙しい毎日の中で
- 心身ともにリフレッシュ
- 新たな一歩を踏み出してみませんか
- 自分自身と向き合う
- 充実した時間
- 〜と言えるでしょう

### 好ましい例

- 「いや、普通に疲れる。」
- 「土曜の予定がないなら、行ってみる？」
- 「気づいたら今日もスマホ6時間。だったら外出よう。」

## 3. BRAND LAYER の適用範囲

| 場所 | Layer |
| --- | --- |
| TOP のヘッドコピー / カテゴリ入口の一言 | Brand |
| Listing 一覧のカード本文 | Fact |
| Listing 詳細の事実表示 | Fact |
| Listing 詳細の「肉体副業メモ」 | Brand（人間記入時のみ） |
| X 投稿候補 / 記事 | Brand（ただし引用する事実は DB の確定 Fact のみ） |

## 4. AVAILABILITY の表示ルール [DECIDED]

Source に「土日勤務可能」とあるだけで「今週土曜日に働ける」と表示しない。

| availability_type | 表示方針 |
| --- | --- |
| `fixed_date` | 日付を明示する（例: 9/19 9:00–12:00） |
| `recurring` | 「土日勤務可能。今週末の募集状況は公式サイトで確認」 |
| `registration` | 「登録制。募集状況は公式サイトで確認」 |
| `unknown` | 日程に関する断定をしない。「日程は公式サイトで確認」 |

## 5. PURPOSE TAGS [DECIDED WITH CAUTION]

ユーザーの入口候補:

- 外に出たい
- 身体を使いたい
- 何も考えたくない
- 普段やらないことをしたい
- 誰かの役に立ちたい

これは user / job matching ではない。**Listing 側の editorial tag** である。

特に「何も考えたくない」は慎重に扱う。介護等、判断・責任・コミュニケーションが必要な
仕事へ安易に付けない。

V0.1 では **AI による自由な purpose tagging を行わない**。必要なら人間編集で付与する。

---

## 6. X 投稿候補の生成ルール（V0.1）

- 生成は `npm run ops:weekend`。テンプレート結合のみ。AI を使わない。
- 元 Web ページを再読込しない。DB に保存した確定 Fact を再利用する。
- 出力は候補であり、人間が確認して手動投稿する。
- テンプレートに入る変数は Fact のみ（日付 / 場所 / 仕事内容 / 報酬有無 / URL）。
